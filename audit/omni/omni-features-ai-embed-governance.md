## 1. AI Features

**Naming note:** The assistant was branded "Blobby" through 2025; docs now consistently use **"Omni Agent"** (Blobby survives as informal branding/customer quotes). AI features are **enabled by default** for organizations.

### AI query/chat surfaces
- **Omni Agent (standalone chat)** — MAJOR. Full-page conversational interface: NL questions, generates queries routed through topics (semantic layer, not text-to-SQL), creates visualizations (incl. KPI tiles), creates dashboards, creates routines, searches existing dashboards before generating new queries (semantic tile matching + live inline previews to promote content reuse), searches Omni docs to answer "how do I" questions, accepts file uploads (.txt/.md/.lkml/.xml/.html) and pasted images as context, voice mode (microphone). Pickers scope to connection → model → topic; auto topic-picking if unset. Model-tier selector (Smarter=Opus / Standard=Sonnet / Faster=Haiku). Sessions saved, shareable by URL (viewer needs Querier+ perms), prompt history via arrow keys, context-window indicator at 75% full, per-field "query field details" transparency panel (definition/SQL of each field the AI selected).
- **Workbook Agent** — MAJOR. Same agent inside workbooks: builds/iterates queries conversationally, creates filters from NL ("exclude deactivated customers"), adds totals, creates measures, summarizes results, generates forecasts and visualizations, converts workbook to an App. Key positioning: AI is interoperable with point-and-click/SQL/spreadsheet UIs — users can drop out of AI at any point.
- **Dashboard Agent** — MAJOR. Chat on published dashboards (floating avatar → split-view; inline panel in SINGLE_CONTENT embeds). Click a chart to scope conversation to that tile; drill, re-aggregate, summarize. Requires "Read result data" setting + per-document "AI on dashboard" ability (controllable globally and per-document).
- **AI dashboard creation** — MAJOR. Agent plans layout, generates queries, publishes complete dashboard; can iterate ("rearrange tiles"); can replicate a dashboard from an uploaded screenshot. Disable per model via `disabled_tools: [create_dashboard_from_chat]`.
- **Apps (AI-built data apps)** — MAJOR (beta, enabled by default for new orgs since June 2026). Describe a custom interactive interface; agent builds it as an app backed by live governed queries. AccessBoost supported on apps.
- **AI visualizations** — MINOR/MAJOR. NL chart creation and configuration: bar/line/area/pie/scatter/heatmap/sankey/funnel/maps/KPIs/tables with conditional formatting, and Markdown/HTML custom layouts.
- **AI summary visualization** — MAJOR. Dashboard tile type that generates an LLM summary of a query's results, with custom context prompts (audience, tone). Summaries cached; recompute only when underlying data changes. Also AI-generated chart subtitles/descriptions and AI-powered visualization annotations (GA June 2026).
- **AI forecasting** — MINOR. NL prompts trigger Omni's internal deterministic statistical forecasting library (no data sent to external forecasting services; multi-period logic: forecasts remainder of current period at daily grain first).
- **AI calculations/formula builder** — MINOR. Describe a calc in plain English → Excel-style formula.
- **Warehouse-native AI functions** — MINOR (beta; Snowflake + Databricks). Table calc functions AI_CLASSIFY, AI_COMPLETE, AI_EXTRACT, AI_SENTIMENT, AI_SUMMARIZE translated to Cortex/Databricks native SQL.
- **AI cron generator** — MINOR. NL → cron expressions in schedule builders.

### AI automation
- **Skills (Agent Skills)** — MAJOR. Modeler-defined, reusable AI processes packaged as one-click buttons in chat, defined in model YAML (`skills:` with `label`, `input`, `description`), from one-line prompts to elaborate multi-step agents (support triage, bug intake, roadmap Q&A). Support `required_access_grants` for visibility control and file uploads (CSV/PDF/JSON/images, processed client-side).
- **Routines (AI Routines)** — MAJOR (launched ~July 2026). Scheduled AI prompts: agent runs a prompt on a cron schedule and delivers a written NL answer via email or Slack. Creatable conversationally ("every Monday 9am email me…"), via UI, API, CLI, Slack Agent, or MCP. Run with creator's permissions. "Conditional Routines" (marketing): notify only when a condition is met. Limits: one destination per routine; not supported in embed.
- **Omni Slack Agent** — MAJOR. `@Omni` in Slack channels/DMs: NL questions answered with charts/tables from the semantic model, follow-ups in thread, feedback (👍/👎), slash commands, routine creation from Slack.
- **AI integrations (agent tool connections)** — MAJOR. Omni Agent can pull context from **Google Drive, Google Calendar, GitHub, Notion, Slack** via per-user OAuth connections (admin-enabled org-wide except Slack, per-user toggles per session). Not available in embedded sessions.

### Semantic-model grounding & AI curation
- **Semantic-model-grounded query generation** — MAJOR (core differentiator). AI emits an abstract "semantic query" (fields/filters/sorts/pivots/topic), never raw SQL; Omni compiles to SQL. Guarantees permission enforcement (row-level security, topic scoping, access grants apply to every AI query), consistent metric definitions, no result-set data needed for generation. Marketing FAQ details a coordinator/agentic architecture (plans actions, selects tools, validates results, multi-step).
- **AI context curation** — MAJOR. `ai_context` free-text at model / topic / view / query-view / dimension / measure level; `synonyms` on fields; `sample_values`; `description`; `sample_queries` (example/golden queries shown as clickable suggestions and used as few-shot context); `ai_fields` to curate/limit fields exposed to the agent per topic; `ai_chat_topics` to whitelist topics available to chat/MCP/embed; user-attribute-personalized context (mustache in ai_context); constants for reusable context; chain-of-thought prompting patterns; topic extensions to limit context windows. Vertical guides published (fintech, retail/ecommerce, SaaS/sales ops, support ops, media/adtech).
- **`ai_settings` model parameter** — MAJOR. Per-model AI tuning: model tier + thinking level per task (`build_configuration`, `analyze_configuration`, `simple_summarize_configuration`), `conversation_prune_length` (context management), `allow_ctes`, `allow_custom_fields`, `disabled_tools`, `query_all_views_and_fields`, `validate_analysis`. Cost/quality tuning-profiles guide.
- **Evals** — MAJOR (also on Azure since July 2026). Prompt sets (≤25 NL prompts, per model), eval runs against any model branch, built-in LLM accuracy judge (pass/fail + rationale; checks hallucinations, date filters, row-limit misreads, mental math, period-over-period errors, ignored instructions), optional per-prompt "expected behavior" reference answers (API-only for now), per-prompt credits/duration, side-by-side run comparison to validate model changes before merging. Two concurrent runs max. Full eval API.
- **Suggestions** — MAJOR. Turns user feedback + sentiment signals from AI sessions into a prioritized (P1–P3) list of model improvements (only AI-context fields: `ai_context`, `description`, `synonyms`, `sample_values`), with rationale, proposed YAML diff, and source chat sessions; one-click "Implement in IDE chat" via Modeling Agent; daily scheduled regeneration; bulk implement/ignore; lifecycle tracking. API endpoints exist.
- **Learn from conversation / Auto-learn** — MAJOR. AI captures business context stated in chat (metric definitions, filter rules, alternate names) and proposes model YAML updates (descriptions, ai_context, synonyms, new dimensions/measures) through a review modal; auto-learn (on by default) proactively surfaces learning moments.
- **Modeling Agent** — MAJOR. Chat panel in the Model IDE: answers questions about model, drafts YAML, fixes validation errors, creates topics/dimensions. Three application modes (Sandbox = review-all-diffs, Review = pause per change, Auto = apply immediately incl. branch creation). Built-in skills: "Optimize topic for AI" (token efficiency/clarity/dedup/sample-query audit) and "Suggest model from query history" (mines Snowflake ACCOUNT_USAGE / Postgres pg_stat_statements to propose views, measures, joins). AI-powered semantic model generation GA July 2026.
- **AI Hub** — MAJOR. Admin center consolidating: settings (Features/MCP/Branding/Model providers/Credits), dashboards (Overview, Quality — reads user questions and feedback, Usage by user/surface, Credit tracking), Suggestions, Evals, Prompt sets. Daily refresh; model must have ≥50 prompts/5 sessions in 30 days to appear.
- **Response rating** — MINOR. 👍/👎 on AI responses (in-app and Slack) feeds Quality dashboard and Suggestions.

### MCP & AI APIs
- **MCP Server** — MAJOR. Remote MCP server exposing governed NL querying to external AI tools. Documented clients: ChatGPT, Claude Desktop, Claude Code, Codex, Cursor, Microsoft Copilot (Copilot Studio), VS Code; also an OpenAI ChatGPT app and Claude connector. Tools: `pickModel`, `pickTopic`, `getData` + `runQuery` (single-shot, **disabled by default**), `askOmni` + `checkStatus` + `listBranches` (full agentic async jobs, can create routines, can target model branches), `searchOmniDocs`, `searchDashboards` (added Aug 2026). Auth: OAuth 2.1 + PKCE (auto-created "MCP OAuth PATs") or API keys; user-level permission passthrough (queries run as authenticated user; `X-MCP-User-ID` impersonation header for org keys). Admin toggles per tool group; disabling kills existing grants.
- **AI APIs** — MAJOR. REST endpoints: generate-a-query (NL→query JSON), create/cancel/status/stream AI jobs (agentic), pick-topic, list/get conversations, AI agent branding, routines CRUD + trigger, evals CRUD, model suggestions CRUD, AI credit controls & usage (org/user/entity-group).
- **Omni CLI + open-source agent skills** — MINOR/MAJOR. CLI (query, model, content, user, schedule management; JSON output; OAuth) plus open-source agent-skills plugin (9 skills, 3 agents: @omni-analyst, @omni-modeler, @omni-admin-agent) for Claude Code, Cursor, Codex, etc. (github.com/exploreomni).

### AI governance, cost & security
- **BYO LLM / model providers** — MAJOR (contract-gated feature). Default: Claude on AWS Bedrock (region-pinned models for data residency; EU users → EU models). Alternatives: Anthropic Direct, Google Vertex AI (WIF), OpenAI (incl. Azure OpenAI/Ollama-compatible base URL + custom model IDs = BYOM), Snowflake Cortex, Databricks Genie, Grok (xAI). Three-tier model config (Smartest/Standard/Fastest). API keys stored encrypted, never redisplayed.
- **AI credit system** — MAJOR. Tokens rolled into "credits", pooled at account level, managed per organization. Controls: org hard cap, auto-downgrade-to-Haiku threshold, per-user default limit (via `omni_ai_credit_limit` system user attribute), individual user limits, embed entity-group defaults and per-group limits (settable via `entityAiCreditLimit` embed URL param). Overage billing at **$1.00/credit** beyond included allotment. Monthly reset (1st, UTC). Credit Tracking dashboard + full API. Not applicable when using a custom provider.
- **AI data security** — MAJOR. No training on customer data; query generation shares only metadata (query metadata, prompt, ai_context, selected-topic field metadata) — never relational/result data; summarization shares a CSV of results (stays within AWS, responses retained 30 days); per-feature data-sharing matrix documented; every AI surface enforces user permissions/RLS.
- **AI feature toggles** — MINOR. Granular org settings: Enable AI, Omni Agent, Chat, Chat-in-navigation (hide standalone chat for embeds), Blank-workbook topic picking, Read result data, File uploads, AI visualization summary, Default connection.
- **AI branding** — MINOR (major for embed). Rename agent, custom icon, intro headline/body, prompt placeholder — applies to embedded chat too.

## 2. Embedded Analytics

- **External embedding via SSO-signed iframe URLs** — MAJOR (core; "Embed" is support-enabled per instance). HMAC-SHA256-signed URLs (embed secret) generated server-side; TypeScript SDK `@omni-co/embed` (official), stateless `/embed/sso/generate-url` API, or manual signing; embed users upserted on login.
- **Standard SSO (1-step)** — MAJOR. Single signed URL creates embed user + session.
- **2-step SSO** — MAJOR. `POST /api/unstable/embed/sso/generate-session` (API-key auth) returns a session token (5-min redeem window) redeemed via a signed URL → 24h/custom session. For sensitive userAttributes and URL-length safety.
- **Embed URL parameters** — MAJOR. Required: `contentPath`, `externalId`, `name`, `nonce`. Others: `connectionRoles` (per-connection role; latest request is source of truth — can downgrade/remove), `modelRoles` (per-model), `userAttributes` (row-level security values), `entity` (tenant grouping; auto-creates shared entity folder + user group), `entityFolderContentRole` / `entityFolderGroupContentRole` / `entityFolderLabel` / `entityGroupLabel` / `preserveEntityFolderContentRole`, `groups`, `mode` (APPLICATION vs SINGLE_CONTENT), `accessBoost`, `filterSearchParam` (preset filters), `linkAccess` (control cross-dashboard linking), `theme` / `customTheme` (inline JSON theme props) / `customThemeId` / `prefersDark`, `timezone`, `uiSettings`, `email` (delivery recipient mapping), `entityAiCreditLimit`, `nonce`.
- **Per-customer data security** — MAJOR. Documented multi-tenant strategies: row-level (access_filters on user attributes, `default_topic_access_filters`), schema-level (dynamic schemas), database-level (dynamic database environments — single-instance dynamic connections guide), model-level (dynamic shared extension models keyed on user attributes). Input columns auto-enforce access-filter fields to prevent cross-tenant leakage. Embed best practices: unique emails per embed user, separate embed user per entity, connectionRoles on every request, default No Access/Viewer.
- **Create Mode (self-service embed)** — MAJOR differentiator. `mode=APPLICATION` gives embed end-users the full Omni app in-iframe: build their own workbooks/dashboards (AI, Excel calcs, SQL, or point-and-click), save to personal or entity Shared folder, share within their entity. Entity isolation via auto-created folders/groups. Role matrix: connectionRole (Restricted Querier = can create) × entityFolderContentRole (Editor/Manager = can publish to entity shared folder). Omni's own in-product "Analytics" section is Create Mode embed dogfooding.
- **SINGLE_CONTENT mode** — MAJOR. Single dashboard/workbook, no navigation/chrome; Dashboard Agent renders inline.
- **Embedded AI chat** — MAJOR. Omni Agent embeddable as standalone page (`contentPath=/chat`), whitelabeled via AI branding; topic curation via `ai_chat_topics`; voice via iframe `allow="microphone"`; watermark-hiding suppresses Omni docs links; AI credit limits per user/entity. Guide for building a full "AI chat agent" embed exists.
- **Theming** — MAJOR. Built-in themes + `customTheme` JSON (page, tile, controls, popovers, buttons properties; dashboard fonts incl. Google Fonts woff2), stored custom themes (`customThemeId`), dark mode (`prefersDark`), application-level theme settings, `appearance-mode` embed event.
- **Vanity domains** — MAJOR. Custom subdomain (e.g., analytics.customer.com) for whitelabeling + first-party cookies (fixes Safari/iOS third-party-cookie blocking); wildcard domains (`*.omni.myapp.com`, beta) for multi-tenant; JS-readable session cookie `__omni_embed_vanity_session` to skip handshakes; enables per-user database OAuth (Snowflake/BigQuery/Databricks) in embeds.
- **Embed events (JS bridge)** — MAJOR. postMessage events both ways: consume (filters changed, page changed, tile drill/download, dashboard download, sidebar, size, status, error — full error payloads for host-side error handling, AI chat start, navigation) and send (update filters, navigate, appearance mode, integration:enable); table/Markdown vizzes can emit custom click events.
- **Embed admin** — MINOR/MAJOR. Multiple named embed secrets (safe rotation, per-environment), session management UI (view/filter/delete sessions; session length 0–576h), embed users tab (view/manage/impersonate embed users), third-party session-recording integrations (FullStory, LogRocket; support-enabled).
- **Deliveries in embed** — MAJOR. Embed users can schedule deliveries/alerts; sender whitelabeling; `email` param populates recipient suggestions; disableable per instance/document.
- **Internal embedding** — MINOR. Simple iframe (login-gated, viewer's own permissions) for wikis/Notion/Salesforce/internal apps; Embed URL Builder for testing.
- **Embed limitations** — session cookie constraints (Safari <26.2 handshake; CHIPS auto on 26.2+), no keyboard shortcuts, routines not in embed, apps not yet embeddable (coming), AccessBoost security caveats for SQL content, content must be topic-based and in Shared hub.
- **AccessBoost** — MAJOR (governance/embed intersection). Lets dashboards/apps bypass viewer connection-role restrictions (view SQL-built content) without bypassing access_filters or access grants (unless grant marked `access_boostable: true`).
- **Marketing positioning for embed**: instant load/caching, define-once metrics, CSS/markdown branding, version control/CI-CD for safe shipping, SOC 2/HIPAA/GDPR, "create new revenue streams / premium pricing tiers", customers launched in 1 week–3 months (Uscreen, ActiveProspect, Standard Metrics, BambooHR, Brevo).

## 3. Sharing, Delivery, Scheduling, Alerts

- **Scheduled deliveries** — MAJOR. Dashboards or single tiles on visual or cron schedules (AWS cron syntax, hourly max frequency by default, timezone control, ~15-min delivery window). One destination per delivery. Test Now / Send Now. Delivery management APIs (CRUD, pause/resume, trigger, transfer ownership, recipients).
- **Destinations** — MAJOR: **Email** (users, external addresses, email-only users), **Slack** (channels/private channels/DMs), **Webhooks** (e.g., Zapier), **SFTP**, **Amazon S3** (cross-account IAM role assumption, no stored credentials, mustache-templated paths/filenames for date-partitioned exports), **Google Sheets** (single tile → existing sheet).
- **Formats** — MAJOR: PNG, PDF (orientation/paper size), XLSX, CSV; expand tables to 1,000 rows, single-column layout, hide filters/title, page selection for multi-page dashboards, per-delivery filter/control values, timezone override, data formatting preservation, "download all possible results" (CSV).
- **Alerts (condition-based deliveries)** — MAJOR. A "Results to check" query is evaluated per scheduled run; condition types: results changed / stayed the same / no results / any results (thresholds achieved by filtering the check query). First run establishes baseline. Unmet condition = recorded "condition unmet", nothing sent.
- **Personalized deliveries (bursting)** — MAJOR. "Personalize delivery with recipient's user attributes": content built separately per recipient with their user attributes (row-level bursting). Org-level modes: Configurable / Always / Never (audit-logged). Recipient resolution ladder: standard/external/embed-SSO user → embed user via `email` param → existing email-only user → auto-created email-only user.
- **Email-only users** — MAJOR. Recipients with no Omni account; auto-created; assignable user attributes (for personalized/filtered deliveries); manageable by API; don't consume licenses; invitable to standard users.
- **Email whitelabeling** — MINOR (major for embed). Custom sender name/email/domain (support-enabled).
- **Domain allowlist** — MINOR. Restrict email delivery recipients to ≤1,000 approved domains with impact preview of existing schedules.
- **Dynamic content (Mustache)** — MINOR. User attributes, date/time, schedule metadata, recipient email in subjects, bodies, filenames, S3 paths, Slack messages.
- **Delivery execution model** — queries run as schedule creator (identity + attributes) unless personalization; fresh-query by default with cache-warming side effect; opt-in "use cached results if available" per model cache policy.
- **Downloads** — MINOR. Dashboard download to PDF/PNG/XLSX/CSV (zip of per-tile CSVs) with same options; per-document/organization ability gating.
- **Content sharing** — MAJOR. Document roles (No Access/Viewer/Editor/Manager/Owner; multiple owners; Owner only for individuals), cascading folder permissions with inheritance (child can be more permissive, never less), org-wide default role, access requests with owner approval flow, document abilities (download/schedule/duplicate/drill/upload/spreadsheets/viewers-see-workbook/request access/require-PR-to-publish/Dashboard Agent/timezone override), custom document URLs/identifiers (stable URLs for embeds), access warnings (dashboards flag tiles Viewers/Restricted Queriers can't run, with reason taxonomy), document + folder permission APIs.

## 4. Governance, Security, Permissions

- **Connection roles (RBAC core)** — MAJOR. Six tiers per connection: No Access, Viewer, Restricted Querier (topic queries only, no SQL), Querier (+SQL), Modeler (+shared model editing), Connection Admin. Base access role per connection + per-model overrides (Model Access) for users/groups. Also Organization Admin (org role).
- **Custom roles** — MAJOR. Variations of base tiers with granular permissions toggled (e.g., "Viewer No Download", "Querier No Upload"): Download, Schedule/Alerts, Use Omni Agent, View IDE, View SQL, Use workbooks, Upload data, Create spreadsheets, Create apps, etc. Priority ordering within tier; usable in embed (`connectionRoles`/`modelRoles`), assignable to users/groups/connection base; resolved role drives licensing.
- **License types** — MAJOR (pricing-relevant). Three tiers derived from highest connection role: Viewer, Standard (Restricted Querier/Querier), Admin/Developer (Modeler/Connection Admin/Org Admin). Email-only users free.
- **User attributes** — MAJOR. Admin-defined per-user variables (string/number, multi-value, defaults — with explicit fail-closed guidance against defaults on security attributes); drive access filters, access grants, field-level conditional SQL/hashing, dynamic connection/schema routing, shared-extension routing, delivery personalization, dashboard filters, Markdown tiles. System attributes: omni_ai_credit_limit, personal-content access, chat panel side, omni_is_org_admin, email, embed entity, omni_user_groups, id, locale, name, timezone. SCIM-syncable (custom ones).
- **Row-level security (access_filters)** — MAJOR. Topic-level (`access_filters`) or model-wide default (`default_topic_access_filters`, incl. unscoped field references); injects WHERE clause per user attribute; `values_for_unfiltered` bypass; SQL LIKE wildcard option; null attribute → error (fail closed).
- **Topic/field-level security (access_grants)** — MAJOR. Named grants on user attributes with allowed_values; applied via `required_access_grants` on topics, views, dimensions, measures, skills; AND/OR conditional syntax (`|`, `&`); model-wide defaults (`default_topic_required_access_grants`); `access_boostable` flag.
- **Column masking** — MINOR/MAJOR. `mask_unless_access_grants` on dimensions: MD5-hash values (preserve joins/aggregation) instead of blocking; PII use case.
- **AccessBoost** — MAJOR (see embed section).
- **Content access controls** — MAJOR (see sharing): folders with cascade + inheritance, org default role, entity folders for embed, "Shared root open" toggle, breadcrumb roots to scope navigation subtrees.
- **Folders & labels** — MINOR/MAJOR. 7-level folder nesting; labels for cross-folder findability with colors/descriptions/metadata, Verified and Homepage (curated "For you") label options.
- **User groups** — MAJOR. Bulk permissioning (connection/model roles + content shares), SCIM-provisioned or API/UI-managed, membership exposed as `omni_user_groups` attribute for data security.
- **Impersonation & View As** — MAJOR. Full-session impersonation of any user incl. embed users and pending invites (admins, not of other admins); lightweight "View As" attribute preview in dashboards.
- **SSO/SAML/OIDC** — MAJOR. Google Workspace, Okta, Microsoft Entra, Rippling (SAML + SCIM provisioning/deprovisioning + user-attribute sync), generic OIDC; default sign-in methods (Google, email link) can be disabled; admin email-fallback toggle; auto-provisioning on first login; deprovisioning handles owned content/schedules.
- **SCIM** — MAJOR. Users + groups via Okta/Entra/Rippling; SCIM-compatible user-group API (`/api/scim/v2/groups`).
- **Audit logs** — MAJOR. Structured JSON event batches delivered to customer S3, GCS, or Azure Blob; ≥1-year retention; event types incl. API requests, query context/execution, dashboard downloads, invites, connection events, org actions, role events, content permission events, embed membership, delivery-personalization changes.
- **Usage analytics ("Analytics")** — MAJOR. Embedded Omni-in-Omni admin workspace: prebuilt dashboards (Overview, Users, Content, Model performance, Schedules, AI logs, Credit Tracking, Changelog, Features/beta flags) on curated production topics; admins can build own analyses, schedule deliveries from them.
- **Session/security settings** — MINOR. Configurable session length (1–4320h non-embed), trash retention window, support access controls (session recording, auto support-user creation, region-limited support logins), billing/security contacts, MFA'd internal ops (marketing).
- **IP controls** — MINOR. Static per-environment egress IPs for allowlisting Omni→database/SFTP/webhook traffic. (No documented end-user login IP-allowlist feature.)
- **Network security** — MAJOR. SSH tunnels and AWS PrivateLink/Azure private connectivity for warehouse access (AWS, Azure, Snowflake, Redshift, Databricks); per-user database OAuth (Snowflake/BigQuery/Databricks) incl. embed via vanity domains; guide for enforcing database-side RBAC through Omni.
- **Change management as governance** — MAJOR. Branch mode, git integration (GitHub incl. GitHub App auth, deploy tokens), required pull requests to publish document changes, drafts/publish workflow, content validator, dynamic environments (dev/staging/prod databases per branch/user attribute).
