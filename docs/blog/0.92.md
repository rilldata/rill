## 🧩 Self-Service Embedded Analytics

The users of your app can now do more than explore embedded dashboards. When your backend passes an `external_user_id` to [`GetIFrame`](/developers/embed/iframe#backend-build-an-iframe-url), each user can schedule their own reports, build their own canvas dashboards and save bookmarks, all limited to the data your [security policies](/developers/build/metrics-view/security) let them see. Each feature is off by default in embeds and is turned on with a feature flag in `rill.yaml`, which can be templated, for example `'{{ .user.embed }}'` to enable it for embed users only.

- **Scheduled reports.** Embed users can [schedule email reports](/developers/embed/iframe#scheduled-reports-in-embeds) of the explore dashboards they can see from the dashboard's export menu, and manage them from a reports page in the navigation bar. Reports run with the `user_email` or `attributes` from the user's latest iframe, always attach the export, and pause when you haven't requested an iframe for the user in 90 days. Enable them with the `reports` feature flag, whose default is now `'{{ not .user.embed }}'`. Projects that already set `reports: true` will show reports to embed users who have an `external_user_id`.
- **Open links back to your app.** Set [`embeds.open_url`](/reference/project-files/rill-yaml#embeds) in `rill.yaml`, and the report creator's email gets an **Open in browser** link to that page in your app. The page passes the link's `rill_open` value as `open` to `GetIFrame`, which [opens the dashboard](/developers/embed/iframe#open-links-in-report-emails) in the state the report captured.
- **Personal canvases (beta).** In iframes with `navigation: true`, embed users can create, edit and delete their own [canvas dashboards](/developers/embed/iframe#personal-canvases-in-embeds) from a menu in the navigation bar, and the project home lists them above the shared dashboards. Only their owner and project admins can open them. Enable them with the `personal_canvases` feature flag.
- **Bookmarks.** Embed users can save a dashboard's filters and time range as a private [bookmark](/developers/embed/iframe#bookmarks-in-embeds) and reopen it later, from the bookmarks menu in the navigation bar, or in the dashboard's top-right corner when the bar is hidden. Enable them with the `embedded_bookmarks` feature flag.
- **Navigation from the host page.** The new `navigate` [postMessage method](/developers/embed/postmessage#supported-methods) opens a dashboard, the project home or the user's reports page in the iframe.
- **Copying from embeds.** The [iframe snippets](/developers/embed/iframe#frontend-embed-the-dashboard) now include `allow="clipboard-write"`. Add it to your `<iframe>` so that Shift+Click copies cell values in Chrome and Edge, which block the Clipboard API in cross-origin iframes without it.

Since reports, canvases and bookmarks are stored per `external_user_id`, use an ID that identifies one security context, such as `<tenant id>:<user id>`; see [User identity in embeds](/developers/embed/iframe#user-identity-in-embeds).

## 📈 Interactive Charts in Claude and ChatGPT

When you ask Claude or ChatGPT about your data through the [Rill MCP server](/guide/ai/mcp), charts now appear in the conversation as [interactive Rill charts](/guide/ai/mcp#interactive-charts-in-claude-and-chatgpt), with the same rendering, number formats and theme as custom viz components in Rill. In fullscreen, change the time grain, the number of top values or the comparison with the previous period, each re-queried from Rill, or switch the chart type and layout instantly. The chart tells the AI what it currently shows, and **Open in Rill** opens the same query in an explore dashboard. Charts work on every Rill MCP endpoint, including the unified endpoint and Rill Developer, in clients that support MCP Apps; other clients, such as Claude Code, keep receiving a table and the link. A built-in `rill-charts` skill guides the AI's choice of chart. Charts are on by default; set `mcp_charts: false` under `features` in `rill.yaml` to turn them off for MCP clients only.

## 📗 Canvas Excel Export (Beta)

Canvas dashboards in Rill Cloud can now be exported as an Excel workbook from the **Export** tab of the **Share** popover, next to the PDF export. The workbook has a dashboard sheet for the canvas, or one per exported tab, laid out like the canvas with its title, time range, filters and an **Open in Rill** link, plus a data sheet for each chart, table, map, custom chart query and leaderboard dimension, written as an Excel table with typed cells and your measures' number formats. Charts become native Excel charts bound to their data sheets (bar, stacked bar, line, area, pie, donut, scatter and combo) or PNG snapshots; heatmaps, funnels, maps and custom charts are always images. KPIs get their value and sparkline. Canvas Excel export is in beta behind the `canvas_excel_export` feature flag.

## ⏱️ Custom Time Grains

A metrics view can now set [`time_grains`](/developers/build/metrics-view/time-series#custom-time-grains) to choose the grains its dashboards offer, including multiples of minutes and hours: `5m`, `10m`, `15m`, `30m`, `2h`, `3h`, `4h`, `6h`, `8h` and `12h`.

```yaml
timeseries: event_time
smallest_time_grain: minute
time_grains: [10m, 30m, hour, day, week]
```

The list replaces the default grains in explore and canvas dashboards, pivot tables and scheduled reports, and the adaptive grain picks only from it. Buckets nest inside hours and days and start at midnight in the dashboard's time zone on every supported OLAP engine. The new grains also work in Metrics SQL (`date_trunc('10m', ts)`), explore URLs and canvas `time_filters`. Without `time_grains`, dashboards keep offering the standard grains at or above `smallest_time_grain`.

## 🇰🇷 Korean Localization

Rill is now available in Korean, our second language after Spanish. More than 2,100 strings have been translated, matching the English interface key for key. Rill Developer picks Korean up from your browser's preferred language, and in Rill Cloud you can choose 한국어 from the language switcher in the user menu.

## 💬 Rename and Delete AI Conversations

Keep your [AI chat](/guide/ai/ai-chat) history tidy. Rename or delete a conversation from the conversation list on the project's AI page, or from the menu next to the conversation title in the chat sidebar. Renaming happens in place and supports `@` references to measures, dimensions and metrics views, as in the chat input.

## ⚡ Performance Improvements

- **Rollups for Metrics SQL and custom APIs.** Metrics SQL, and so custom APIs built on it, put time filters in `WHERE`, which made [rollup selection](/developers/build/metrics-view/rollups#how-rollup-selection-works) skip every rollup. Rill now moves `>=` and `<` bounds on the primary time dimension into the query's time range whenever that leaves the results unchanged, so these queries, and API callers that bound time in `where`, can read from a matching rollup instead of the base table.
- **Lighter query cache.** Sizing a query result for the cache no longer serializes it, which uses about 3.4 times less memory and runs 2.3 times faster per cache miss (2.7 MB down to 0.8 MB for 10,000 rows).

## Bug Fixes and Improvements

### Explore / Dashboards

- Fixed explore and canvas dashboards failing to load on metrics views without time bounds, such as an empty table or one whose rows a security policy hides, and on data with placeholder dates such as `0001-01-01`
- Fixed explore dashboards failing with `missing required dimension` when the metrics view has a measure that requires a dimension, such as a rolling window; leaderboards, totals, the dimension table and its exports now leave such measures out
- Fixed explore dashboards, bookmarks and links failing with `not found` errors after a measure or dimension was removed from the metrics view while Rill Cloud kept serving the explore's last valid version
- Fixed comparing by the time dimension in the time dimension detail view failing on ClickHouse with a duplicate alias error
- Fixed time series charts going blank when comparing values of a dimension whose name contains a dot, such as a Druid nested column
- Fixed pivots failing with a 500 error when sorted by a measure while a row dimension has a `uri`
- Fixed pivots and their exports failing when sorted by a field the pivot no longer shows, such as a removed measure or a comparison column with comparison off; they now use the default sort
- Fixed pivots crashing when a field was placed twice in rows or columns, and drag-reordering a pivot field leaving a second copy behind
- Fixed expanding a pivot row with no sub rows sending a failing query
- Fixed leaderboards, comparison series and filter chips failing to render when a dimension was listed twice, such as `?dims=publisher,publisher`, or when comparing values such as `0` and null

### Canvas

- A canvas with `comparison_mode: time` now opens with the first `comparison_offsets` entry declared for its default range in [`time_ranges`](/reference/project-files/canvas-dashboards#time_ranges), such as `rill-PM` for `rill-MTD`
- Fixed one table or pivot component with an invalid spec, such as one that references a removed measure, stopping the whole canvas from rendering for viewers
- Fixed pie, donut and funnel charts failing with `binary condition must have exactly 2 expressions` when their dimension has no rows for the selected range or filters; they now render empty
- Fixed donut and pie charts with an "Other" slice (`show_other: true`) throwing an error on every data update
- Fixed templated markdown components showing their raw template source while it resolves, or for good when the template renders nothing

### Alerts and Reports

- Added a `where_resource` filter to [`resource_status` alerts](/developers/build/alerts#resource-status), so an alert can watch specific resources, such as `model/orders` or `metrics_view/*`, instead of the whole project
- Fixed alert pages failing to open in Rill Cloud when the alert's criteria compare against the previous period, such as a percent change
- Fixed the links in alert and report emails failing to open dashboards whose metrics view has no time dimension
- Fixed weekly alerts and scheduled reports created in a language other than English being saved with an invalid schedule when the day was left at its default

### Metrics Views

- Fixed sub-day grains in UTC failing on ClickHouse metrics views whose time dimension is a `Date` or `Date32` column, which broke canvas KPI comparisons
- Fixed rollups being used for one-sided time ranges they only partly cover, and a rollup that ends exactly at the base table's last row dropping that row
- Fixed Metrics SQL `now()` filtering at the wrong time on DuckDB when the runtime does not run in UTC
- Fixed an empty `IN` or `NOT IN` filter in Metrics SQL being read back as an `IS NULL` check

### AI / LLM

- Made the AI analyst's charts keep the dashboard's filters when you chat from a dashboard, so a chart no longer shows unfiltered data next to filtered findings
- Made the AI analyst reply in the language of the question instead of opening its answers in English
- Fixed tool calls to the unified MCP server failing from recent ChatGPT clients
- Fixed **Open in Rill** links from AI answers failing when the query was sorted by a calculated measure or a field the dashboard doesn't show
- Fixed the conversation list failing to load when a conversation title was cut in the middle of a multi-byte character
- Fixed negative feedback from the downvote dialog being sent without the rated message, its categories or its comment

### Rill Developer

- Fixed the model inspector sending failing row and column count queries for a model's connectors and for models that have not produced a table yet

### Cloud

- Showed the compute price next to the seat price on the billing page's Starter and Growth plan cards, with a link to the full pricing breakdown
- Stopped the scheduled report dialog, the Status pages and the Share popover from requesting members, user groups and billing details the user can't read, which caused 403 errors; for those users, the Share popover lists only the project's members and the Status page hides the cluster size
- Fixed a dashboard being replaced by an error page when a background refresh of the project failed, for example after waking a laptop; network errors now show the reconnect banner instead
- Fixed scheduled reports, bookmarks and PDF export failing to open in tabs left open across a Rill Cloud update; the tab now reloads once into the new version

### Embedding

- Removed the Rill name from the AI memory dialog, so embedded dashboards don't show Rill branding there

### Security

- Limited project variables (`.env`) to templates in connectors and models; custom APIs, canvas component properties and `if` conditions, alerts, reports and templates sent through the API can no longer read them, and the parser reports an error where a project file references them (see [Referencing Environment Variables](/developers/build/connectors/templating#referencing-environment-variables))
- Fixed private assets, such as project deploy archives, being downloadable without permission in organizations that have a public project
- Upgraded `go-jose` to v4.1.6 to resolve Dependabot alerts

### Documentation

- Clarified how to connect Claude Code and the Claude desktop app to Rill Developer in the [agentic quickstart](/developers/get-started/ai-quickstart)
- Documented [downloading canvas components as PNG](/guide/dashboards/canvas#download-a-component-as-png), moving and duplicating [tab groups](/developers/build/dashboards/canvas#tab-groups), and [setting per-viewer conditions in the visual editor](/developers/build/dashboards/canvas#set-conditions-in-the-visual-editor)
