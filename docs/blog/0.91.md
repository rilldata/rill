## 🧠 AI: Chat Memory, External MCP Servers and Amazon Bedrock

- **Chat memory.** AI chat now [remembers](/guide/ai/ai-chat#memory) the preferences and clarifications you share, such as how you like numbers formatted or what "active" means to your team, and applies them in later conversations in the same project. You can review, edit, add or delete memories at any time, or pause memory altogether. Memories are private to you and the project, and they never override the project's `ai_instructions`.
- **External MCP servers.** Rill's AI agents can now use tools from [external MCP servers](/guide/ai/external-mcp) such as Linear, GitHub, Slack, Notion or a service your team runs, alongside Rill's built-in tools. In Rill Cloud, each user connects a server with their own account from the chat's **External tools** menu, and tokens are stored encrypted per user. Internal servers can use a service token from the project's environment variables instead, and security policies control who can use which servers and tools.
- **Amazon Bedrock and Claude prompt caching.** The new [`bedrock` AI connector](/developers/build/connectors/services/bedrock) runs all of Rill's AI features, from chat to generating metrics views and dashboards, on a model in your own AWS account. Set `ai_connector: bedrock` in `rill.yaml`, or add it from the **Add AI connector** dialog in Rill Developer. Claude connectors gain a [`prompt_caching`](/developers/build/connectors/services/claude#prompt-caching) option that reuses the tools, system prompt and conversation between the steps of an answer, which typically lowers cost and latency.
- **Suggested prompts and skills.** Give users a head start with clickable [starter prompts](/developers/build/ai-configuration#suggested-prompts) in `rill.yaml` or on a dashboard, where a prompt picks up the dashboard's current filters and time range. Typing `/` now opens the skill picker in every chat, including dashboard, embedded and developer chats.

## 🔒 Fine-Grained Security Controls for Canvas Components

One canvas can now serve several audiences. Add a simple security rule using [`if` condition](/developers/build/dashboards/canvas#show-content-to-some-viewers-only) over user attributes to any row, tab group, tab or component, and each viewer sees only what is meant for them. Fields a viewer is not allowed to query are simply left out of tables, pivots, KPI grids and leaderboards instead of breaking the component. In the visual editor, set a condition from the **Visible when** field and check the result for each audience with **View as**.

## 🎨 Canvas Dashboards: Column Settings, Adaptive Time Grain and PNG Downloads

- **Column settings for tables and pivots.** Tables and pivots now give you [per-column control](/developers/build/dashboards/canvas-widgets/data#column-widths-styling-and-sort) over width, label, alignment, number format and wrapping, plus component-level options to fit columns to the widget, wrap headers and set the initial sort. Resize or sort a column in the visual editor and the change is written back to the YAML.
- **Adaptive time grain.** The new **Adaptive** grain, now the default in canvas and explore dashboards, follows the selected time range so charts always show a readable number of points. Picking a specific grain works as before. Canvas dashboards also gain a grain selector in the filter bar and the widget inspector, and a widget can set its own grain in [`time_filters`](/developers/build/dashboards/canvas-widgets/data).
- **Download as PNG.** Any canvas component can be downloaded as a PNG, with or without a header showing the dashboard title, time range, comparison and filters.
- **Move and duplicate tab groups.** Drag whole tab groups around in the canvas editor, or duplicate one with all of its tabs.

## 📊 Custom Visualizations (Beta)

[Custom viz components](/developers/build/dashboards/canvas-widgets/custom-viz) take canvas dashboards beyond the native chart widgets. A custom viz is a reusable component that declares its params, such as a metrics view or a measure, queries data with Metrics SQL and describes the chart with a chart type and encodings. Rill compiles it to Vega-Lite with [Flint](https://github.com/microsoft/flint-chart), Microsoft's open-source chart compiler, which works out scales, axes, colors and layout from your data and takes number formats from your metrics view. Pick a starting point from the gallery of [chart types](/developers/build/dashboards/canvas-widgets/custom-viz/chart-types), from waterfall charts and box plots to heatmaps and Gantt charts, or ask the AI assistant to write one against your metrics views. Add it to a canvas from **Your components** in the widget menu, and when you need full control, **Convert to Vega-Lite** turns it into an [editable Vega-Lite spec](/developers/build/dashboards/canvas-widgets/custom-viz/vega-lite). Custom viz is in beta behind the `custom_components` feature flag; dashboards render the components they reference whether or not the flag is set.

## ⚖️ Exact Measures on Demand for Approximate Uniques

Approximate distinct counts and quantiles keep dashboards fast on large tables, but sometimes you also need the exact number. A measure can now define an [`exact_expression`](/developers/build/metrics-view/measures/exact-measures) next to its approximate `expression`. Dashboards keep showing the fast approximate value with a `≈` chip, and [clicking the chip](/guide/dashboards/explore/exact-measures) computes the exact value for the current filters and time range, wherever you are: big numbers, leaderboards, pivots or canvas widgets. The API accepts `exact: true` per measure, and the AI assistant uses it when you ask for exact or reconciled numbers.

## 📧 Email Attachments for Reports and Alerts

Report and alert emails can now carry their data as a CSV, Excel or Parquet file, so recipients no longer need to follow a link.

- **Reports.** Select **Attach file to emails** when creating or editing a scheduled report, or set [`export.attach`](/reference/project-files/reports#export) in the [report YAML](/guide/reports/exports#attaching-the-file-to-emails).
- **Alerts.** Alert emails used to show only the first matching row. Select **Attach matching rows to emails** to send [all of them](/guide/alerts#attaching-the-matching-rows), optionally up to a row limit, or set [`export`](/reference/project-files/alerts#export) in the alert YAML.

Attachments are capped at 10 MB, and Slack notifications are unchanged.

## ⚡ Performance Improvements

- **Faster ClickHouse lookup dimensions.** The new [`lookup_group_by_key`](/developers/build/metrics-view/dimensions/lookup#grouping-by-the-key-first-with-lookup_group_by_key) option resolves dictionary values once per key instead of once per row, with identical results. In a 20-million-row benchmark, a sum grouped by a lookup dimension ran more than twice as fast and listing the dimension's values ran 19 times faster. It is opt-in per dimension, so compare query times on your own data.
- **Faster comparisons on ClickHouse.** Comparison queries over `UUID` dimensions and `Decimal` measures now aggregate the comparison range only for the values on screen by using an optimized two phase query with explicit value filter, as other types already did.
- **Faster Databricks connections.** The first connection to a serverless SQL warehouse is more than twice as fast now that the upgraded driver detects Lakehouse//RT warehouses itself, and a failed connection check is retried on the next query instead of being cached.
