## Overview

[Databricks](https://docs.databricks.com) is a unified data and AI platform built on top of Apache Spark and the lakehouse architecture. Rill connects to Databricks SQL warehouses using the [Databricks SQL Go driver](https://github.com/databricks/databricks-sql-go) to ingest data into Rill's embedded engine.

## Authentication

Rill authenticates to Databricks using a [personal access token](https://docs.databricks.com/aws/en/dev-tools/auth/pat). The token must have access to the SQL warehouse and to the catalogs and schemas you intend to query.

### Using the UI

1. Click **Add Data** in your Rill project
2. Select **Databricks** as the data source type
3. In the authentication step:
   - Enter the **Server hostname** of your SQL warehouse (e.g. `dbc-xxxxxxxx-xxxx.cloud.databricks.com`)
   - Enter the **HTTP path** of your SQL warehouse (e.g. `/sql/1.0/warehouses/xxxxxxxxxxxxxxxx`)
   - Paste your **Personal Access Token**
   - Optionally specify a default **Catalog** and **Schema**
4. In the data model configuration step, enter your SQL query
5. Click **Create** to finalize

After the model YAML is generated, you can add additional [model settings](/developers/build/models/source-models) directly to the file.

### Manual Configuration

If you prefer to configure manually:

**Step 1: Create connector configuration**

Create `connectors/databricks.yaml`:

```yaml
type: connector
driver: databricks

host: "dbc-xxxxxxxx-xxxx.cloud.databricks.com"
http_path: "/sql/1.0/warehouses/xxxxxxxxxxxxxxxx"
token: "{{ .env.DATABRICKS_TOKEN }}"
catalog: "main"     # optional
schema: "default"   # optional
```

:::info Lakehouse//RT warehouses
Lakehouse//RT (real-time) warehouses only support the Statement Execution API (SEA)
protocol and reject the default Thrift protocol. Rill **auto-detects** this: if a
warehouse rejects Thrift, the connector transparently switches to the SEA backend — no
configuration needed. Ordinary DBSQL warehouses keep using Thrift.
:::

**Step 2: Add credentials to `.env`**

```bash
DATABRICKS_TOKEN=dapi...
```

<EnvPullTip />

Then, [create your first model](#create-your-first-model).

### Connection String (DSN)

For advanced configuration, you can specify a single DSN instead of the individual fields above. The DSN cannot be combined with `host`, `http_path`, `token`, `catalog`, or `schema`.

```yaml
type: connector
driver: databricks

dsn: "{{ .env.DATABRICKS_DSN }}"
```

```bash
DATABRICKS_DSN=token:dapi...@dbc-xxxxxxxx-xxxx.cloud.databricks.com:443/sql/1.0/warehouses/xxxxxxxxxxxxxxxx?catalog=main&schema=default
```

See the [Databricks SQL Go driver](https://github.com/databricks/databricks-sql-go) documentation for the full list of supported DSN parameters.

## Per-user OAuth (Rill Cloud)

By default, all dashboard queries run with the connector's token. With per-user OAuth, each viewer signs in to Databricks once, and their dashboard queries run with their own Databricks token, so Unity Catalog grants, row filters, and column masks apply per viewer.

**Step 1: Register an app connection in Databricks**

A Databricks account admin does this in the account console:

1. Go to **Settings → App connections** and click **Add connection**.
2. Set the redirect URL to `https://admin.rilldata.com/connectors/oauth/callback`.
3. Select the `sql` scope.
4. Generate a client secret and copy the client ID and secret.
5. Set the refresh token TTL to 90 days. With the 7-day default, viewers must sign in again weekly.

**Step 2: Configure the connector**

```yaml
type: connector
driver: databricks

host: "dbc-xxxxxxxx-xxxx.cloud.databricks.com"
http_path: "/sql/1.0/warehouses/xxxxxxxxxxxxxxxx"
token: "{{ .env.DATABRICKS_TOKEN }}"  # service credential
auth: oauth
oauth_client_id: "{{ .env.DATABRICKS_OAUTH_CLIENT_ID }}"
oauth_client_secret: "{{ .env.DATABRICKS_OAUTH_CLIENT_SECRET }}"
oauth_scopes: [sql, offline_access]  # optional, this is the default
```

```bash
DATABRICKS_OAUTH_CLIENT_ID=...
DATABRICKS_OAUTH_CLIENT_SECRET=dose...
```

`auth: oauth` requires `host`, `http_path`, `token`, `oauth_client_id`, and `oauth_client_secret`, and cannot be combined with `dsn`. Rill still uses `token` to parse and validate your project, such as reconciling models and metrics views. Models that read from this connector are built with the service `token`, so their output is visible to all viewers, and Unity Catalog rules for viewers do not apply to it.

Viewers who have not signed in see a prompt to sign in to Databricks in place of the data. Signing in opens a popup; the data loads when it completes, without a page refresh. Viewers sign in separately in each project, and are prompted again if the OAuth settings change or Databricks rejects the token refresh.

:::note Not supported yet
Alerts, scheduled reports, embedded dashboards, and "View as" do not work with `auth: oauth`; queries from them fail instead of using the service credential. Caching is disabled for this connector.
:::

## Create Your First Model

Once your connector is configured, create a model to define what data to pull.

Create `models/databricks_data.yaml`:

```yaml
type: model
connector: databricks

dev:
  sql: SELECT * FROM main.my_schema.my_table LIMIT 10000

sql: SELECT * FROM main.my_schema.my_table
```

After creating the model, you can add additional [model settings](/developers/build/models/source-models) directly to the file.

## Appendix

### Finding your SQL Warehouse Connection Details

In the Databricks workspace:

1. Navigate to **SQL Warehouses** and select the warehouse you want to use.
2. Open the **Connection details** tab.
3. Copy the **Server hostname** and **HTTP path**.

To create a personal access token:

1. Click your profile icon and open **Settings**.
2. Go to **Developer → Access tokens** and click **Generate new token**.
3. Provide a name and lifetime, then copy the token. Databricks only shows the token once.

For service principal authentication and other auth methods, see the [Databricks SQL driver authentication docs](https://github.com/databricks/databricks-sql-go#authentication).

### Unsupported Data Types

The Databricks ingestion path streams results as Arrow and writes them to Parquet. Columns of type `TIME` are not currently supported — exclude them from your query or cast them to a different type (for example, `STRING` or `TIMESTAMP`).

:::warning Check your service principal permissions
The user or service principal associated with the personal access token needs `SELECT` on the tables being read and `USE CATALOG` / `USE SCHEMA` on the parent catalog and schema. See the [Unity Catalog privileges reference](https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/privileges) for the full list.
:::
